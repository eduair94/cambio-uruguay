# Alertas de búsqueda (autos, motos, ventas, bajas de precio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the rental saved-search alert engine to used cars, used motos and homes for sale, and add opt-in price-drop notifications to every search kind.

**Architecture:** The existing kind-dispatched engine (`app/server/utils/rentalAlert*.ts`) keeps its index/cursor/outbox/lease/delivery. Three new kinds plug in through one source module (inventory + matching per catalog). Price drops are synthetic event ids generated by the index from a new per-listing price ledger, so they reuse the same cursor, baseline and outbox.

**Tech Stack:** Nuxt 4 / Nitro tasks, mongoose 9, vitest, Vuetify 4, vue-i18n local messages.

**Spec:** `docs/superpowers/specs/2026-10-17-alertas-de-busqueda-design.md`

## Global Constraints

- Everything lives in `app/`; no imports from the root backend; no new pm2 job (Nitro `rentals:alerts` handles all kinds).
- Collection names stay `rentalalert*`; new collection `rentalalertprices`.
- Kinds: `'rental-search' | 'rental-opportunity' | 'car-search' | 'moto-search' | 'sale-search'`.
- Candidate ids: `car:<key>`, `moto:<key>`, `sale:<key>`, `rent:<source>:<id>` (unchanged).
- Drop id: `<base>~drop~<currency>~<amount>~<previousAmount>`.
- Drop rule: current < lowest seen × (1 − 0.01) AND current ≥ lowest seen × (1 − 0.5); currency change resets silently.
- `priceDrops` defaults: missing on stored docs ⇒ `false`; new drafts ⇒ `true` except `rental-opportunity` (always `false`).
- Account limit 20 (was 10).
- Public repo: no revenue figures anywhere.
- Copy in es/en/pt, Rioplatense voseo in es.

## Review Focus

1. A catalog publish that finishes mid-scan (cars hourly :29, sales hourly :17) must not seed events — inventory throws when `generatedAt` changed. Test in Task 3.
2. Facebook car whose deduced currency flips USD↔UYU must not produce a drop. Test in Task 2.
3. Rental subscriptions stored before this change (no `priceDrops` field) must never receive drops. Test in Task 4.
4. A listing that is new and drops inside the same digest goes once, as the drop. Test in Task 4.
5. Moto email links: only an `https://` Mercado Libre Uruguay permalink is linked; anything else falls back to the search URL. Test in Task 5.
